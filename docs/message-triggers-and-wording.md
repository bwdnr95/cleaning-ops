# 메시지 발송 정리 (도급사 검토용) — 언제 · 어떤 상태 · 어떤 문구

- 갱신일: 2026-07-12
- 목적: 어떤 상황에서 어떤 문자/알림톡이 고객·협력사에게 나가는지 한눈에 보고, **문구 수정 요청**을 받기 위함.
- 현재 채널: SOLAPI 카카오 알림톡 9종 승인 완료. 알림톡 실패 시 본문 길이에 따라 SMS/LMS로 폴백하며, 고객 접속 링크 재발급은 승인 템플릿이 아닌 전용 LMS로 보낸다.

## 1. 발송 메시지 한눈에

| # | 메시지 | 받는 사람 | 언제 나가나(트리거) | 발송 방식 | 부가 효과 |
|---|--------|-----------|----------------------|-----------|-----------|
| 1 | 예약확정 안내 | 고객 | 협력사가 **[작업 일정 확인]** 클릭 | 자동 발송 | 주문 상태 → **작업예정** |
| 2 | 전날 안내 | 고객 | 방문일 하루 전 오전 10시(Asia/Seoul) | 자동 발송 | 이미 발송/진행 중이면 중복 발송하지 않음 |
| 3 | 협력사 배정 안내 | 협력사 | 협력사가 배정된 주문을 **협력사확인중**으로 등록 | 자동 발송 | 협력사 작업확인 링크와 발송 이력 기록 |
| 4 | 사진 링크 발송 | 고객 | 주문상세 **[사진 링크 발송]** 또는 사진검수 화면 버튼 (공개 사진 1장 이상) | 미리보기 → 확인 발송 | 상태 변경 없음(재발송 가능) |
| 5 | 잔금 안내 | 고객 | 협력사가 필수 증빙 등록 후 **[작업 완료]** 클릭(실제 미수 잔금이 있는 주문) | 자동 발송 | 주문 상태 → **고객전달필요** |
| 6 | 견적 안내 | 고객 | 주문 저장 후 주문상세 **[견적 안내]** 버튼 | 미리보기 → 확인 발송 | 견적서엔 도급가 미포함 |
| 7 | 협력사 고객정보(미입금) | 협력사 | 협력사관리 정산탭 **[고객정보 전송]** → 모달 | 미리보기 → 확인 발송 | 협력사 담당자 연락처 우선 |
| 8 | AS 요청 처리 | 협력사 | 운영자가 고객 AS 접수 확인 후 처리 | 자동 발송 | 협력사 작업 링크 포함 |
| 9 | AS 접수 안내 | 고객 | 운영자가 고객 AS 접수 확인 후 처리 | 자동 발송 | 고객 주문 링크 포함 |
| 10 | 고객 접속 링크 | 고객 | 토큰 회전·링크 분실 시 주문상세 또는 주문목록 일괄 발송 | 운영자 확인 후 LMS | 상태 변경 없음, 발송 이력·고객 링크 발송 이벤트 기록 |

> 협력사 배정, 예약확정, 전날 안내, 작업완료 후 잔금 안내, AS 처리 안내는 자동 발송한다. 사진 링크·견적·협력사 고객정보는 운영자가 명시적으로 발송한다.
> 고객은 인증된 예약 페이지에서 AS 내용을 먼저 접수한다. 이때 주문 상태와 매출 집계는 바꾸지 않고 `as_intake_pending`으로 **고객 확인 필요** 큐에 표시하며, 협력사·고객 알림톡은 아직 발송하지 않는다. 운영자가 주문 상세에서 접수 내용을 확인하고 **AS 요청 처리**를 실행한 시점에 주문을 `고객확인필요`로 바꾸고 8·9번을 각각 한 번 발송한다.
> 관리자 방문일 입력만으로는 예약확정 안내가 나가지 않는다. 예약확정은 협력사의 **[작업 일정 확인]** 이벤트만 트리거로 사용한다.
> 작업완료는 비포 사진, 애프터 사진, 고객 서명이 모두 있어야 가능하며 실제 미수 잔금이 있는 주문에만 잔금 안내를 보낸다. AS 재작업은 AS 접수 이후, 협력사 재배정 건은 새 협력사의 배정·확인 이후 새로 등록한 비포·애프터 사진과 새 고객 서명이 모두 필요하다.
> 고객 링크 인증값은 전화번호 뒷자리이므로 고객용 일정확정·전날안내의 연락처 치환값에는 뒷자리를 넣지 않는다. `customer_visible_payment=false`이면 일정확정 알림톡의 금액 치환값은 `-`로 보낸다.
> 상태 반영 직후 프로세스가 중단돼도 60초 주기의 복구 작업이 배정·예약확정·AS·잔금 발송 누락을 탐지한다. 성공 로그는 재발송하지 않는다. SOLAPI PENDING은 timeout·5xx·불완전 응답뿐 아니라 API 결과 저장 전 프로세스 중단도 사업자 수락 여부를 자동으로 확정할 수 없으므로, 유예시간 뒤 **결과 불명**으로 전환하고 같은 업무 epoch의 자동·수동 재발송을 막는다. 운영자는 SOLAPI 콘솔에서 수신번호·요청시각을 대조한 뒤 발송 이력의 **[발송 확인]** 또는 **[미발송 확인]**으로 확정한다. 미발송 확인 때만 재발송이 열리며, 일정 재확인·새 AS·새 작업완료 같은 새 epoch가 시작되면 이전 불명 결과는 새 발송을 막지 않는다.

> 협력사 확인 뒤 방문일·요청시간 또는 협력사가 바뀌면 기존 확인 epoch를 무효화하고 다시 `협력사확인중`으로 전환한다. 새 협력사의 작업확인 전에는 변경된 일정의 예약확정 알림을 보낼 수 없다.

## 2. 실제 문구 (수정 검토 대상)

`[클린잡]`로 시작하며, `{ }`는 주문 데이터로 자동 치환됩니다. 링크는 고객 토큰이 서버 접근 로그에 남지 않도록 `https://cleanjob.tono-operation.com/c#token=<고객별 코드>` 형태를 사용합니다.
구형 `/c/<코드>` 및 query token 링크는 인증에 사용하지 않으며 `/c`로 정리됩니다. `0027` 배포 마이그레이션은 기존 고객 토큰을 전부 새 난수로 회전해 과거 access log의 토큰을 무효화합니다. 따라서 배포 완료 후 진행 중 주문과 사진 열람·AS 지원 대상인 서비스완료 주문에는 10번 LMS로 신규 링크를 재발송해야 합니다.

**1) 일정확정 안내**
```
[클린잡] {고객명}님, 예약 일정이 확정되었습니다.
서비스: {서비스명}
방문: {방문일정}
주소: {주소}
예약 확인: {고객링크}
```

**2) 전날 안내**
```
[클린잡] 내일 방문 예정 안내드립니다.
서비스: {서비스명}
방문: {방문일정}
요청사항과 안내는 아래 링크에서 확인해주세요.
{고객링크}
```

**3) 협력사 배정 안내**
```
[클린잡] {협력사명}에 신규 작업이 배정되었습니다.
방문: {방문일정}
서비스: {서비스명}
고객: {고객명}
주소: {주소}
요청사항: {요청사항 또는 -}
작업 일정 확인: {협력사링크}
```

**4) 사진 링크 발송**
```
[클린잡] {고객명}님, {서비스명} 작업 사진 확인이 준비되었습니다.
아래 링크에서 연락처 뒷자리 인증 후 확인해주세요.
{고객링크}
```

**5) 잔금 안내**
```
[클린잡] {고객명}님, {서비스명} 작업이 완료되었습니다.
잔금: {잔금}
결제 및 작업 내역 확인: {고객링크}
```

**6) 견적 안내**
```
[클린잡] {고객명}님 견적 안내드립니다.
서비스: {서비스명}
소비자가(VAT {포함/별도}): {금액}
할인가: {할인가}
계약금: {계약금} / 잔금: {잔금}
방문: {방문일정}
```

**7) 협력사 고객정보(미입금)**
```
[클린잡] {담당자/협력사명}님, 미입금 고객 정보를 전달드립니다.
고객: {고객명} ({고객 전체 연락처})
방문: {방문일정}
주소: {주소}
요청사항: {요청사항 또는 -}
```

**8) AS 요청 처리(협력사)**
```
[클린잡] {협력사명}에 {고객명}님의 {서비스명} AS 작업이 배정되었습니다.
상세 내용은 인증된 협력사 링크에서 확인해주세요.
```

**9) AS 접수 안내(고객)**
```
[클린잡] {고객명}님, {서비스명} AS 접수가 처리되었습니다.
상세 내용은 고객 링크에서 확인해주세요.
```

**10) 고객 접속 링크(LMS 전용)**
```
[클린잡] {고객명}님, 예약·작업 내역 확인 링크입니다.
연락처 뒷자리 인증 후 확인해주세요.
{고객링크}
```

> 승인된 AS 알림톡 템플릿에는 AS 메모·연락처 치환문자가 없으므로 전체 내용은 인증된 링크에서 확인한다. 애플리케이션이 알림톡의 명확한 초기 실패 뒤 직접 보내는 문자(SMS/LMS)에는 AS 메모 요약(UTF-8 1,000바이트 이내)이 포함된다. SOLAPI가 자체 처리하는 비동기 폴백 본문에는 메모가 보장되지 않으므로 링크를 기준으로 운영한다.

## 4. 참고 (개발 메모)
- 문구 원본: `backend/app/services/messages.py` → `_render_content()`.
- 발송 방식 분류 근거: 미리보기-확인은 `OrderDetailPage` 미리보기 모달 경유, 6·7은 버튼 즉시 발송.
- 알림톡 전환 시: 승인된 카카오 템플릿 변수는 `domain/message_templates.py`를 기준으로 보낸다. 명확한 초기 실패에는 애플리케이션 SMS 폴백을 시도하고, 결과 불명 상태에는 중복 방지를 위해 즉시 폴백하지 않는다.
