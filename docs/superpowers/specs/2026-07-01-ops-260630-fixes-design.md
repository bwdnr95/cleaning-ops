## #1 — "결제 확인 필요"에서 미도래(미래 방문일) 건 제외

**현황**: "결제 확인 필요" = 대시보드 KPI `payment_check_needed`(`DashboardService`) + 주문목록 `payment_check` 탭(`order_page._matches_status_tab`). 둘 다 **`payment_status ∈ (pending, balance_pending, unpaid)` + 취소 제외**로만 집계 → **방문일 무관**이라 미래 방문 건도 포함되어 혼란.

**변경**: 두 곳 모두에 **"방문일이 미래(오늘 이후)면 제외"** 조건 추가. 단 **방문일 없음(미배정)은 유지**(결제 확인이 필요할 수 있음). 즉 포함 조건 = `payment_status ∈ CHECK` AND `취소 아님` AND **(`scheduled_date` 없음 OR `scheduled_date ≤ 오늘(KST)`)**.

- 백엔드 1: `app/services/dashboard.py`의 `payment_check_needed=self._count(...)`에 날짜 조건 추가. 오늘 = `business_today()`(이미 대시보드가 KST today 사용). 조건:
  `(Order.scheduled_date <= today) | Order.scheduled_date.is_(None)`.
- 백엔드 2: `app/services/order_page.py` `_matches_status_tab`의 `payment_check` 분기에 동일 조건(Python):
  `and (order.scheduled_date is None or order.scheduled_date <= today)`. `today`는 `business_today()`(분기 평가 시 계산하거나 호출부에서 주입 — **카운트와 동일 기준**이어야 함, AGENTS.md).
- **카운트 = 드릴다운 일치**가 핵심(같은 정의). 프론트 변경 없음(대시보드 클릭 → payment_check 탭 그대로, 이제 양쪽 다 미도래 제외).

**테스트**: 미래 방문 + 미납 주문은 카운트·payment_check 탭에서 제외; 과거/오늘 방문 + 미납은 포함; 방문일 없음 + 미납은 포함; 취소는 계속 제외. 대시보드 카운트와 order_page 필터 결과 일치.

## #2 — 협력사 정산 0원 라인에 그룹(고객) 합계 회색 표시

**현황**: 협력사 정산 그리드(`PartnersPage`, `settlements.items`)는 라인별로 `소비자가(job.consumer_price)`·`도급가(job.partner_price)`를 표시. 한 그룹(고객)에 여러 라인인데 금액이 한 라인에만 입력되면 **다른 라인이 0원**으로 보임. → 0원 칸에 **그 라인이 속한 그룹의 합계**를 작은 회색으로 보조 표시.

**데이터(백엔드)**: `PartnerSettlementItemRead`(`schemas/partner.py`)에 필드 2개 추가:
- `group_consumer_total: float` = 그 그룹의 모든 라인 `order_consumer_total` 합(삭제·취소 제외).
- `group_partner_total: float` = 그 그룹의 모든 라인 `partner_payment_amount` 합(삭제·취소 제외).
- `services/partner_settlements.py` `list_settlements`: 결과 주문들의 **고유 group_id별로** `OrderGroupRepository.list_lines(group_id)`를 모아 위 두 합계를 계산(취소/삭제 제외, `Decimal`), `to_settlement_item`에 전달해 채움. (그룹 합계는 **그 그룹 전체 라인** 기준 — 보통 같은 협력사 다건이라 자연스러움.)

**표시(프론트)**: `PartnersPage` 그리드의 소비자가/도급가 셀에서, 라인 금액이 `0`이고 그룹 합계가 `> 0`이면 금액 아래에 작은 회색:
```jsx
<GridCell mono>
  {formatWon(job.consumer_price)}
  {job.consumer_price === 0 && job.group_consumer_total > 0 && (
    <div style={{ fontSize: 10.5, color: 'var(--text-tertiary)', fontWeight: 400 }}>
      그룹 {formatWon(job.group_consumer_total)}
    </div>
  )}
</GridCell>
```
도급가 칸도 동일(`job.partner_price`/`job.group_partner_total`). `api/admin.ts`(또는 partners API 타입)의 settlement item 타입에 `group_consumer_total`/`group_partner_total` 추가.

**테스트**: 한 그룹 2라인(금액 라인1=120000, 라인2=0) → 정산 item의 group_consumer_total=120000이 두 라인 모두에 실림; 단일 라인 그룹은 group_total=line 금액. 취소/삭제 라인은 합계 제외. 프론트 0원 셀에 회색 그룹합계 렌더(typecheck/build).
