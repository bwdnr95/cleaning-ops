- [ ] KST 기준 today (`datetime.now(KST).date()`) 사용 — `date.today()` 잔존 없는가?

## 7. 운영 흐름 시나리오 (수동 워크스루)

리뷰어가 직접 다음 흐름을 따라가며 막힘이 없는지 확인하고 그 결과를 보고서에 기록.

### 시나리오 A — 신규 주문 → 견적 발송 → 정산
1. 사이드바 '+ 신규 주문 등록' 버튼 클릭.
2. 고객 정보 입력 → 카테고리(청소) → 신축 입주청소 → 수량 30 입력 → 총 금액·도급가·계약금 자동 채움 확인.
3. 할인가 9,000 입력 → 총 금액 차감 확인.
4. VAT 포함 선택.
5. 저장 후 견적서 발송 클릭 → 발송이력에서 도급가 변수가 노출되지 않음을 확인.
6. 주문 완료 처리 후 협력사 관리 → 해당 협력사 상세 → 정산 대상 1건이 추가된 것 확인.
7. 정산 처리 → 상태 변경 + timeline 기록 확인.

### 시나리오 B — 미납 고객 협력사 통보
1. 결제 상태가 미납인 주문을 협력사 상세 페이지에서 확인.
2. 행 액션 메뉴에서 '협력사에 고객정보 전송' 클릭 → 미리보기 확인 → 전송.
3. 발송이력에 신규 메시지 기록.
4. 주문 timeline 에 `partner_unpaid_notice_sent` 확인.

### 시나리오 C — 정렬/필터 회귀
1. 오늘 작업 + 미납 1건 + 미래 작업 다건 + 과거 완료 1건 시드.
2. 진입 시 미납 → 오늘 → 미래 순서 확인. 과거 완료는 안 보임.
3. '전체' 토글 시 과거 완료 노출.
4. 방문일 ↓ 토글 시 내림차순 확인.

각 시나리오의 결과(스크린샷 1장 이상)를 리뷰 보고서에 첨부.

## 8. 종합 판정

다음 중 하나를 선택하여 PR 본문 최상단과 리뷰 보고서 마지막에 기록한다.

- ✅ **머지 가능** — 모든 항목 통과 또는 ⚠ 경미한 이슈만 존재, 후속 이슈로 트래킹 가능.
- ⚠ **조건부 머지** — 차단성 결함 없음, 단 X 개의 ⚠ 항목을 동일 PR 추가 커밋으로 해결.
- ❌ **머지 불가** — 차단성 결함 존재. 결함 목록과 후속 작업 계획을 명시.

## 9. 발견된 이슈가 있을 때 처리 절차

1. ❌ 차단성: 동일 PR 후속 커밋으로 즉시 수정. 수정 후 영향 받은 체크리스트 항목을 재검증.
2. ⚠ 경미: 별도 GitHub 이슈 등록 (또는 `.master/next_session_plan.md` 백로그 추가) 후 PR 본문에 링크.
3. 진단 자체가 틀렸음을 발견하면 본 체크리스트 또는 작업 지시서에 "보정 메모" 섹션을 추가하여 다음 세션이 혼란을 피하도록 한다.
