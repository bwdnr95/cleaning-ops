# Cleaning Ops Control Center 프로젝트 기획서

## 0. 프로젝트 핵심 정의

### 프로젝트명

**Cleaning Ops Control Center**  
국문명: **청소 주문·협력사·고객안내 통합 운영관리 시스템**

### 제품 목표

현재 엑셀, 전화, 카카오톡, 문자로 분산되어 있는 청소업체의 운영 흐름을 하나의 웹 시스템으로 통합한다.

핵심 업무 흐름은 다음과 같다.

```text
고객 문의 접수
→ 전화상담 및 상품/금액 입력
→ 협력사 일정 확인
→ 고객 일정 확정
→ 고객 안내 발송
→ 전날 해피콜/방문 안내
→ 협력사 작업 진행
→ 비포/애프터 사진 업로드
→ 관리자 사진 검수
→ 고객에게 완료 사진 링크 전달
→ 결제/완료 처리
```

이 시스템은 단순 데이터 입력기가 아니라, **운영자가 오늘 처리해야 할 일을 놓치지 않게 만드는 컨트롤타워**여야 한다.

---

## 1. 현재 엑셀 기반 업무 분석

업로드된 엑셀은 `전체 raw data` 시트 기준으로 다음 컬럼 구조를 가진다.

- 상태
- 접수일
- 방문예정일
- 요청시간
- 담당팀
- 상품명
- 주소
- 평수/대수
- 상품상세/특별요청
- 유입경로
- 고객명
- 연락처
- 총계약금액
- 계약금
- 잔금
- 현장추가금
- 부가세
- 결제확인
- 입금정보
- 증빙자료
- 업체명
- 결제금액 별도
- 결제확인

현재 엑셀은 단순 고객명단이 아니라 다음 기능을 동시에 수행하고 있다.

1. 주문 접수대장
2. 작업 일정표
3. 협력사 배정표
4. 고객 상담 기록
5. 상품/서비스 기록
6. 결제 확인표
7. 협력사 지급금액 기초자료
8. 작업 완료 관리표

따라서 웹 시스템은 이 엑셀의 정보를 그대로 옮기는 수준을 넘어서, **업무 단계별로 재구성**해야 한다.

## 2. 사용자 역할

### 2.1 관리자

청소업체 내부 관리자 또는 상담 직원.

관리자는 시스템의 중심 사용자다.

관리자가 해야 하는 일:

- 신규 주문 등록
- 고객 정보 입력
- 상품/서비스 선택
- 계약금, 잔금, 총금액 입력
- 협력사 배정
- 방문예정일/요청시간 관리
- 주문 상태 변경
- 고객 안내 문자/알림톡 발송
- 협력사 작업 배정 안내 발송
- 비포/애프터 사진 검수
- 고객에게 완료 사진 링크 발송
- 결제 상태 확인
- 발송 이력 확인
- 오늘 처리할 업무 큐 확인

관리자 화면의 핵심은 **엑셀보다 빠르고, 누락이 덜 나고, 현재 업무 상태가 한눈에 보이는 것**이다.

---

### 2.2 협력사

실제 청소, 에어컨청소, 입주청소, 줄눈, 탄성코팅 등을 수행하는 외부 협력업체.

협력사가 해야 하는 일:

- 본인 계정으로 로그인
- 본인에게 배정된 작업만 확인
- 방문일, 요청시간, 주소, 상품명, 요청사항 확인
- 작업 전 비포 사진 업로드
- 작업 후 애프터 사진 업로드
- 작업 상태 변경
- 작업 완료 처리
- 현장 메모 입력

협력사에게 보여주면 안 되는 정보:

- 전체 주문 리스트
- 다른 협력사의 작업
- 고객 총계약금액
- 마진 구조
- 내부 입금정보
- 유입경로
- 증빙자료 전체
- 협력사별 정산 통계

협력사 화면은 모바일 최적화가 중요하다. 복잡한 관리자 화면처럼 보이면 안 된다.

---

### 2.3 고객

청소 서비스를 신청한 최종 고객.

고객은 회원가입하지 않는다. 고객은 문자/알림톡으로 받은 링크를 통해 본인 주문 페이지에 접근한다.

고객이 확인할 수 있는 것:

- 예약 상태
- 서비스명
- 방문예정일
- 요청시간
- 주소
- 요청사항
- 결제 안내
- 방문 전 안내사항
- 작업 완료 후 비포/애프터 사진
- 문의 전화 버튼

고객이 할 수 없는 것:

- 직접 주문 수정
- 일정 변경
- 취소 요청 자동 처리
- 결제
- 채팅
- 회원가입
- 사진 삭제

고객 페이지는 이 프로젝트의 브랜드 체감 포인트다. 고객이 링크를 눌렀을 때 “이 업체 체계적이다”라고 느껴야 한다.

## 3. 제품 경험 원칙

### 3.1 관리자 경험 원칙

관리자는 로그인하자마자 오늘 할 일이 보여야 한다.

관리자 대시보드는 단순 통계가 아니라 **업무 큐** 중심이어야 한다.

대시보드에서 바로 보여야 하는 것:

- 오늘 작업 예정
- 내일 방문 안내 대상
- 협력사 확인 중인 주문
- 사진 검수 대기
- 고객 전달 필요
- 결제 확인 필요
- 이번 달 완료 건수
- 이번 달 총계약금액

관리자는 “어디부터 봐야 하지?”라고 생각하지 않아야 한다.

---

### 3.2 협력사 경험 원칙

협력사는 업무 현장에서 휴대폰으로 사용한다.

따라서 화면은 다음 원칙을 따른다.

- 버튼은 크고 명확해야 한다.
- 오늘 작업과 예정 작업이 바로 보여야 한다.
- 주소, 시간, 요청사항이 명확해야 한다.
- 사진 업로드는 비포/애프터 구분이 쉬워야 한다.
- 작업 완료 버튼이 명확해야 한다.
- 금액, 내부 메모 등 불필요한 정보는 숨긴다.

---

### 3.3 고객 경험 원칙

고객 페이지는 간단하지만 고급스러워야 한다.

고객 페이지에서 중요한 것은 기능보다 신뢰감이다.

고객은 다음을 느껴야 한다.

- 내 예약이 제대로 접수되어 있다.
- 방문일과 시간이 명확하다.
- 업체가 체계적으로 관리하고 있다.
- 작업 완료 사진을 편하게 확인할 수 있다.
- 문의할 방법이 명확하다.

---

## 4. 전체 업무 플로우

### 4.1 주문 접수 플로우

1. 고객이 전화 또는 상담 채널로 문의한다.
2. 관리자가 관리자 페이지에서 신규 주문을 등록한다.
3. 고객명, 연락처, 주소, 상품명, 평수/대수, 특별요청을 입력한다.
4. 상품/세부항목/수량을 선택한다.
5. 기본 단가가 있으면 참고값으로 불러온다.
6. 최종 총계약금액, 계약금, 잔금은 관리자가 수동 조정할 수 있다.
7. 상태는 `신규접수` 또는 `상담중`으로 저장된다.

---

### 4.2 협력사 확인 플로우

1. 관리자가 주문 상태를 `협력사확인중`으로 변경한다.
2. 협력사 후보를 선택하거나 담당팀을 지정한다.
3. 협력사와 전화/카톡으로 가능 여부를 확인한다.
4. 확정되면 담당 협력사를 지정한다.
5. 방문예정일과 요청시간을 확정한다.
6. 상태를 `일정확정`으로 변경한다.
7. 고객 일정 확정 안내를 발송한다.
8. 협력사 작업 배정 안내를 발송한다.

---

### 4.3 전날 안내 플로우

1. 방문예정일 하루 전 주문이 대시보드의 `전날 안내 대상`에 노출된다.
2. 관리자가 대상 주문을 확인한다.
3. 고객에게 전날 방문 안내 문자/알림톡을 발송한다.
4. 발송 완료 후 상태 또는 플래그가 `전날안내완료`로 저장된다.

---

### 4.4 작업 진행 플로우

1. 협력사가 로그인한다.
2. `내 작업`에서 오늘 작업을 확인한다.
3. 작업 상세 페이지에서 주소, 시간, 상품명, 요청사항을 확인한다.
4. 작업 전 비포 사진을 업로드한다.
5. 작업 후 애프터 사진을 업로드한다.
6. 작업 메모를 입력한다.
7. `작업 완료` 버튼을 누른다.
8. 주문 상태는 `사진검수대기`가 된다.

---

### 4.5 사진 검수 및 고객 전달 플로우

1. 관리자는 `사진검수` 메뉴에서 업로드된 사진을 확인한다.
2. 비포/애프터 사진이 적절하면 고객 공개를 승인한다.
3. 승인된 사진만 고객 페이지에 표시된다.
4. 관리자는 고객에게 작업 완료 사진 확인 링크를 발송한다.
5. 발송 후 상태는 `고객전달완료`가 된다.
6. 내부적으로 최종 확인 후 `서비스완료`로 변경한다.

## 5. 상태값 정의

주문 상태는 시스템의 핵심이다.

| 상태 | 의미 |
|---|---|
| 신규접수 | 새 문의 또는 주문이 등록된 상태 |
| 상담중 | 금액, 일정, 상품 상담이 진행 중인 상태 |
| 협력사확인중 | 협력사 가능 일정 확인 중 |
| 일정확정 | 고객과 일정이 확정된 상태 |
| 전날안내필요 | 방문예정일 하루 전 안내가 필요한 상태 |
| 전날안내완료 | 고객에게 전날 방문 안내가 완료된 상태 |
| 작업예정 | 작업일이 도래했거나 예정된 상태 |
| 작업진행 | 협력사가 작업 진행 중인 상태 |
| 사진검수대기 | 협력사가 사진을 업로드했고 관리자의 검수가 필요한 상태 |
| 고객전달필요 | 사진 검수는 완료됐고 고객에게 전달해야 하는 상태 |
| 고객전달완료 | 고객에게 완료 사진 링크가 발송된 상태 |
| 서비스완료 | 내부적으로 완료 처리된 상태 |
| 취소 | 취소된 주문 |

### 상태 설계 원칙

- 상태는 업무 누락을 막기 위한 장치다.
- 모든 주문은 반드시 하나의 상태를 가진다.
- 상태 변경 시 타임라인 로그가 남아야 한다.
- 문자/알림톡 발송은 상태와 연결되어야 한다.
- 완료된 주문도 검색 가능해야 한다.

## 6. 관리자 기능 상세

### 6.1 관리자 로그인

필수 기능:

- 이메일 또는 아이디 로그인
- 비밀번호 로그인
- 관리자 계정 관리
- 로그아웃

권한은 1차에서 단순화한다.

관리자 권한:

- 전체 주문 조회
- 전체 수정
- 발송
- 사진 승인
- 협력사 관리
- 상품 관리

---

### 6.2 관리자 대시보드

대시보드는 시스템의 첫인상이다. 고급스럽고 실무적인 화면이어야 한다.

#### 상단 KPI 카드

- 오늘 작업 예정 건수
- 내일 안내 대상 건수
- 사진 검수 대기 건수
- 고객 전달 필요 건수
- 결제 확인 필요 건수
- 이번 달 완료 건수
- 이번 달 총계약금액

#### 업무 큐

업무 큐는 다음 항목으로 구성한다.

1. 협력사 확인 필요
2. 내일 안내 발송 필요
3. 오늘 작업 예정
4. 사진 검수 대기
5. 고객 전달 필요
6. 결제 확인 필요

각 큐는 클릭하면 해당 주문 리스트로 이동한다.

#### 오늘/내일 작업 리스트

대시보드 하단에는 오늘과 내일 작업을 보여준다.

표시 항목:

- 시간
- 고객명
- 상품명
- 주소
- 담당 협력사
- 상태
- 바로가기

---

주문관리는 엑셀을 대체하는 메인 화면이다.

#### 리스트 컬럼

- 상태
- 접수일
- 방문예정일
- 요청시간
- 담당팀/협력사
- 상품명
- 주소
- 평수/대수
- 고객명
- 연락처
- 총계약금액
- 계약금
- 잔금
- 결제확인
- 사진상태
- 고객전달상태

#### 필터

- 상태
- 방문예정일 기간
- 접수일 기간
- 담당 협력사
- 상품명

### 6.4 주문 등록/수정

주문 상세 화면은 섹션형 폼으로 구성한다.

#### 섹션 1. 기본 상태

- 상태
- 접수일
- 방문예정일
- 요청시간
- 담당팀/협력사

#### 섹션 2. 고객 정보

- 고객명
- 연락처
- 주소
- 유입경로

#### 섹션 3. 상품 정보

- 상품명
- 세부항목
- 평수/대수
- 상품상세/특별요청

#### 섹션 4. 금액 정보

- 총계약금액

## 8. 고객 페이지 기능 상세

### 8.1 고객 접근 방식

고객은 회원가입하지 않는다.

문자/알림톡으로 받은 고유 링크를 클릭한다.

보안 방식:

1. 고객 링크 접속
2. 연락처 뒷자리 4자리 입력
3. 일치하면 주문 페이지 표시

---

### 8.2 고객 페이지 구성

#### 상단

- 업체 로고 또는 업체명
- 예약 상태 배지
- 고객명
- 문의 전화 버튼

#### 예약 정보 카드

- 서비스명
- 방문예정일
- 요청시간
- 주소
- 요청사항

#### 결제 안내 카드

노출 여부는 관리자가 선택 가능하면 좋다.

기본 노출 항목:

- 총금액
- 계약금
- 잔금
- 결제 상태

단, 입금정보나 내부 증빙 메모는 노출하지 않는다.

#### 방문 전 안내사항

고객에게 전달할 준비사항을 표시한다.

예:

- 방문 전 현장 출입 가능 여부 확인
- 전기/수도 사용 가능 여부
- 귀중품 보관 안내
- 에어컨청소 시 실외기 위치 확인
- 입주청소 시 현장 짐 정리 안내

#### 작업 완료 사진

작업 완료 전:

> 작업 완료 후 비포/애프터 사진이 이곳에 표시됩니다.

작업 완료 후:

- 비포 사진
- 애프터 사진
- 기타 사진

관리자가 승인한 사진만 표시한다.

## 9. 문자/알림톡 발송 정의

### 9.1 발송 원칙

- 처음부터 완전 자동보다 관리자 확인 후 발송 버튼 방식이 안전하다.
- 발송 전 미리보기를 제공한다.
- 발송 성공/실패 이력을 저장한다.
- 외부 발송 API 장애 시 실패 상태를 남긴다.
- 알림톡 템플릿 승인이 지연될 수 있으므로 SMS/LMS 대체 발송이 가능해야 한다.

---

### 9.2 발송 유형 1: 고객 일정 확정 안내

#### 발송 시점

관리자가 상태를 `일정확정`으로 변경한 뒤 발송.

#### 메시지 예시

```text
[업체명] 예약이 확정되었습니다.

서비스: {{상품명}}
방문일: {{방문예정일}}
시간: {{요청시간}}
주소: {{주소}}

예약 정보 확인:
{{고객페이지링크}}
```

---

### 9.3 발송 유형 2: 고객 전날 방문 안내

#### 발송 시점

방문예정일 하루 전. 대시보드의 `전날 안내 대상`에서 일괄 발송 가능.

#### 메시지 예시

```text
[업체명] 내일 방문 예정 안내드립니다.

서비스: {{상품명}}
방문일: {{방문예정일}}
시간: {{요청시간}}

방문 전 안내사항은 아래 링크에서 확인하실 수 있습니다.
{{고객페이지링크}}
```

---

### 9.4 발송 유형 3: 협력사 작업 배정 안내

#### 발송 시점

관리자가 협력사를 배정한 후 발송.

#### 메시지 예시

```text
신규 작업이 배정되었습니다.

방문일: {{방문예정일}}
시간: {{요청시간}}
상품: {{상품명}}
주소: {{주소}}

작업 상세 확인:
{{협력사작업링크}}
```

---

### 9.5 발송 유형 4: 고객 완료 사진 안내

#### 발송 시점

협력사 사진 업로드 → 관리자 검수 → 고객 공개 승인 → 발송.

#### 메시지 예시

```text
[업체명] 작업이 완료되었습니다.

비포/애프터 사진은 아래 링크에서 확인하실 수 있습니다.
{{고객페이지링크}}
```
